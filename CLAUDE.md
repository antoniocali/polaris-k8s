# CLAUDE.md — polaris-k8s

Kubebuilder operator for **Apache Polaris** (REST Iceberg catalog). Manages Polaris resources as Kubernetes CRDs so the catalog is configurable through GitOps + ArgoCD instead of ad-hoc REST calls.

This file orients Claude Code sessions running inside this repo.

## What's here today

- **API contract.** All 12 CRDs are defined under `api/v1alpha1/`. Generated CRD YAML lives in `config/crd/bases/`.
- **Polaris OpenAPI specs are vendored** under `openapi/` (Apache Polaris 1.4.1 — management + catalog planes).
- **Polaris HTTP client** under `internal/polaris/` — `polaris.NewClient(cfg)` returns a wrapper with `.Management` and `.Catalog` typed sub-clients (auto-generated by `oapi-codegen`), OAuth client-credentials token caching, TLS config, and a `polaris.APIError` type with `IsNotFound`/`IsConflict`/`IsUnauthorized`/`IsRetryable` helpers.
- **All 12 reconcilers are implemented** under `internal/controller/*_controller.go`. Each one resolves refs through the parent chain, builds a Polaris client, GET/POST/PATCH/DELETE against the right plane, manages a `polaris.k8s.calific.io/finalizer` for cascade deletion, and surfaces `Ready`/`Synced` (and per-kind extras like `AuthValid`, `CredentialsWritten`) status conditions.
  - Drift policy on `properties` maps is **authoritative** — keys not in spec get removed Polaris-side.
  - Deletion cascades to the Polaris-side resource by default (no `spec.deletionPolicy` field yet).
  - Schema/partition spec drift on `PolarisTable` and SQL drift on `PolarisView` are **not** yet detected — initial create is full-fidelity, but updates to those fields require a manual drop+recreate. Properties drift on tables/views is also TODO (the Iceberg `CommitTable` machinery is the missing piece).
- **Unit tests** for every reconciler live in `internal/controller/*_unit_test.go` using a fake kube client + an `httptest.Server` fake Polaris. **Envtest specs** in `internal/controller/*_controller_test.go` drive each reconciler against a real Kubernetes API server (real CRD schema, status subresource, finalizer semantics) with only the Polaris HTTP backend faked. **`test/e2e`** reconciles the full 12-kind object graph against a real Apache Polaris server running as a sibling Kind container.
- **Two install paths, one source of truth.** `config/` is the kubebuilder source of truth for CRDs (`config/crd`) and RBAC (`config/rbac`); `make deploy IMG=...` / `kubectl apply -k config/…` is the plain-kustomize path. `dist/chart/` is a Helm chart generated from the same `config/` output via the `helm.kubebuilder.io/v2-alpha` plugin (`make helm-deploy IMG=...`, or `kubebuilder edit --plugins=helm/v2-alpha` to regenerate) — **never hand-edit files under `dist/chart/`**, they're regenerated the same way `zz_generated.deepcopy.go` is.

## API conventions (read before editing types)

The skill `kubebuilder-api-design` is the source of truth for marker patterns. Conventions specific to this repo:

- **Single API group:** `polaris.k8s.calific.io`, version `v1alpha1`. New kinds go in the same package.
- **Namespaced everywhere.** No cluster-scoped CRDs. Same-namespace references are the default; the optional `Namespace` field on each `*Ref` allows cross-namespace where needed.
- **Purpose-built `*Ref` types** in `api/v1alpha1/refs.go`. **Do not** use `corev1.LocalObjectReference` or `corev1.ObjectReference` — that pattern is explicitly avoided per the kubebuilder-api-design skill.
- **Hierarchy via parent ref**, not path arrays. `PolarisNamespace.spec.parentRef` chains namespaces; `PolarisGrant.spec.target` uses a discriminated union (`type` + matching `*Ref`).
- **Polaris-side name defaults to `metadata.name`** when `spec.name` is unset. Naming pattern is `^[a-zA-Z0-9_-]+$`.
- **Every CRD has** `+kubebuilder:subresource:status`, a `[]metav1.Condition` field with `listType=map`/`listMapKey=type`, `observedGeneration`, printer columns for `Ready` and `Age`, and `categories=polaris` so `kubectl get polaris` returns everything.
- **Cross-field rules → CEL.** `+kubebuilder:validation:XValidation` for things like "storageType=S3 requires .s3 to be set". See `PolarisCatalog.StorageConfig` and `PolarisGrant.Spec` for examples.
- **List semantics matter for SSA.** Use `+listType=set` for unique-item lists, `+listType=map`+`+listMapKey=...` for keyed structs. Required for clean ArgoCD diffs.

## Common operations

### After editing any `api/v1alpha1/*_types.go`

```sh
make generate    # regenerate zz_generated.deepcopy.go
make manifests   # regenerate config/crd/bases/*.yaml
go build ./...   # sanity check
```

Never edit `zz_generated.deepcopy.go` directly — `make generate` overwrites it.

### Adding a new CRD kind

```sh
kubebuilder create api --group polaris --version v1alpha1 --kind PolarisFoo --resource --controller
```

Then rewrite `api/v1alpha1/polarisfoo_types.go` following the convention above (Spec, Status, root markers, printer columns, `init()` registering with SchemeBuilder).

### Adding a field

1. Edit the relevant `*_types.go`. Apply kubebuilder markers.
2. Run `make generate manifests`.
3. Inspect `config/crd/bases/<kind>.yaml` — confirm required-ness, enums, defaults, and list semantics rendered as intended.
4. If you added a cross-field constraint, also confirm it appears under `x-kubernetes-validations:` with the expected `rule:` and `message:`.

### Running tests

```sh
make test        # envtest-backed Ginkgo suite (downloads kube-apiserver + etcd binaries on first run)
go test ./api/... -count=1   # fast API-level checks (no envtest)
```

## Hierarchy (mental model)

```
PolarisConnection ──┬─► PolarisCatalog ──┬─► PolarisNamespace (self-nestable via parentRef) ──┬─► PolarisTable
                    │                    │                                                    ├─► PolarisView
                    │                    │                                                    └─► PolarisPolicy
                    │                    └─► PolarisCatalogRole ◄── PolarisGrant (privilege on catalog|namespace|table|view)
                    │
                    ├─► PolarisPrincipal (writes generated creds to spec.credentialsSecretRef)
                    └─► PolarisPrincipalRole

PolarisPrincipalRoleBinding: Principal ── grants ──► PrincipalRole
PolarisCatalogRoleBinding:   PrincipalRole ── inherits ──► CatalogRole
```

## Out of scope (do not implement unless asked)

- Schema/partition/SQL drift detection on `PolarisTable` and `PolarisView` (requires Iceberg `CommitTable`/`CommitView` machinery).
- Webhook validation beyond CEL.
- GitOps/ArgoCD config — not this repo's concern; wire the Helm chart (or `config/`) into whatever GitOps tooling you use.
- Multi-version migration (`v1alpha1` → `v1beta1` → `v1`). Until we ship, all schema changes happen on `v1alpha1` in place.

## Gotchas

- **`kubebuilder create api`** wires the new kind into `cmd/main.go` and `internal/controller/`. If you skip the controller scaffold (`--controller=false`), you must add the SchemeBuilder import yourself.
- **`zz_generated.deepcopy.go` errors** after a type change usually mean a non-deepcopy-able field (raw interface, function value). Use pointer-to-struct or one of the supported `apiextensionsv1.JSON` / `runtime.RawExtension` types instead.
- **CEL rules are validated at admission**, not at `go build`. A broken CEL expression only surfaces when you `kubectl apply` a CR — always test by applying a sample.
- **Defaults only apply on create.** Existing CRs in the cluster keep their old values; a controller mutation is the only way to retro-apply.
- **Namespace nesting requires reconciler logic** to enforce that `parentRef` resolves to the same `catalogRef`. The CRD schema can't express that — it's a reconciler invariant.
- **All `*Ref` namespaces default to the referrer's namespace at *reconcile* time**, not at admission. Until reconcilers exist, the empty namespace stays empty in `kubectl get -o yaml`.
- **`spec.name` defaulting to `metadata.name`** is also a reconciler responsibility — markers can't express it.
